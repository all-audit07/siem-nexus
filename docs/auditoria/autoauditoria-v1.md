# Autoauditoría de SIEM NEXUS v1.0

Revisión de seguridad del propio proyecto antes de publicarlo (04/11/2026). Criterio: ISO/IEC 27001:2022, Anexo A.

| ID | Condición | Criterio | Causa | Efecto | Recomendación | Estado |
|---|---|---|---|---|---|---|
| H-01 | Contraseñas y JWT secret en texto plano en `docker-compose.yml` | 5.17 Información de autenticación | Configuración inicial sin gestión de secretos | Exposición al publicar el repositorio | Mover a `.env` excluido de Git y rotar | Cerrado: movidos y rotados |
| H-02 | El backend usaba una contraseña por defecto si faltaba la variable de entorno | 8.28 Codificación segura | Valores de respaldo de desarrollo | Credencial válida embebida en el código | Eliminar valores por defecto de secretos | Cerrado |
| H-03 | Healthcheck de MySQL con contraseña embebida y resultado positivo aunque el acceso fuera denegado | 8.16 Actividades de seguimiento | `mysqladmin ping` no valida la autenticación | Control que aparentaba funcionar sin comprobar nada | Usar la variable de entorno y validar el resultado | Cerrado |
| H-04 | Contraseñas de las cuentas demo escritas en el código de la página de login | 5.17 y 8.28 | Función de autocompletado para demostración | Cualquier visitante las obtiene del JavaScript del cliente | Eliminar contraseñas del cliente y cambiarlas | Cerrado (v1.0.1): contraseñas retiradas del cliente y cambiadas. Evidencia: build sin credenciales y contraseñas antiguas rechazadas (401) |
| H-05 | Hashes bcrypt y clave maestra de SQL Server en scripts de datos iniciales | 5.17 | Scripts de laboratorio reutilizados | Ataque de diccionario fuera de línea | Sustituir por marcadores | Cerrado en el repositorio; clave maestra pendiente de cambio |
| H-06 | Capturas del borrador del informe mostraban contraseñas y JWT secret | 5.17 | Evidencias tomadas sin revisión de datos sensibles | Exposición en documentos compartidos | Revisar evidencias antes de publicarlas y rotar lo expuesto | Cerrado: secretos rotados |
| H-07 | La rotación de contraseñas dejó MySQL inaccesible temporalmente | 8.32 Gestión de cambios | El secreto nuevo se aplicó antes de guardarlo | Pérdida de acceso; recuperada sin pérdida de datos | Respaldo previo y guardar el secreto antes de aplicarlo | Cerrado: procedimiento corregido |
| H-08 | Acceso de respaldo en el cliente: si el backend no respondía, el login aceptaba `admin` con una contraseña fija y creaba una sesión local | 5.17 y 8.5 Autenticación segura | Modo demo de desarrollo no retirado | Credencial expuesta y autenticación sin servidor (sin acceso a datos: el backend exige un token válido) | Eliminar el modo demo y mostrar un error si el servidor no responde | Cerrado (v1.0.1) |
| H-09 | No hay bloqueo de cuenta por intentos fallidos; solo un límite por IP (10 intentos cada 2 min) | 8.5 Autenticación segura | Diseño inicial sin contador por cuenta | Un password spraying lento o distribuido no se frena | Contador de fallos por cuenta con bloqueo temporal y alerta | Cerrado (v2.0): bloqueo de 15 min al 5.º fallo, configurable con LOGIN_MAX_FAILURES y LOGIN_LOCK_MINUTES |
| H-10 | El login comprueba el estado de la cuenta antes que la contraseña | 8.5 Autenticación segura | Orden de las validaciones | Enumeración: revela si una cuenta existe y está inactiva sin conocer la contraseña | Validar primero la contraseña y responder con un mensaje genérico | Cerrado (v2.0): mensaje genérico, contraseña validada antes que el estado y tiempo de respuesta igualado |
| H-11 | El informe técnico atribuía la prueba RBAC al usuario viewer `pedro.silva`, que estaba inactivo; la prueba real se hizo con `alesso` (analyst) | 5.28 Recopilación de evidencias | Evidencia registrada sin verificar el usuario | Conclusión correcta (un usuario sin rol admin no puede borrar) con atribución inexacta | Registrar usuario, rol y hora de cada prueba | Cerrado: informe corregido |
| H-12 | El cambio de contraseñas de las cuentas demo aplicó durante unos minutos el hash de una contraseña vacía (script de bash ejecutado en zsh) | 8.32 Gestión de cambios | Sin validar la entrada ni el intérprete del script | Riesgo mitigado: la API rechaza contraseñas vacías (400) | Validar entradas en los scripts y probarlos en el intérprete real | Cerrado |
